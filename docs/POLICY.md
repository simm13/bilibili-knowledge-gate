# 判定策略与调参

## 一、总原则

1. **严格白名单**：只有"能学到东西"的才算知识性内容。
2. **降级不放松**：模型不可用时退回规则判定；规则也判不出来时，**弱知识词不自动放行**。
3. **可解释**：每条裁决都带 `reason` + `source`（`rule:game` / `rule:ent` / `rule:knowledge` / `llm` / `rule:live:area` …），可追溯可审计。

## 二、五层规则

| 层 | 变量 | 作用 |
|---|---|---|
| 1 | `GAME_TITLE_RE` | 具体游戏名（《原神》《王者荣耀》…）→ 立即非知识 |
| 2 | `KNOWLEDGE_STRONG_RE` | 强知识白名单（"教程/讲解/公开课/知识点"…）→ 立即知识 |
| 3 | `ENTERTAIN_RE` | 娱乐黑名单（"实况/搞笑/吃播/鬼畜/翻唱/宅舞"…）→ 非知识 |
| 4 | `GAME_RE` | 泛游戏词（"游戏实况/攻略/开黑/上分"…）→ 非知识 |
| 5 | — | 都不命中 → 交 LLM；LLM 挂 → 弱知识词只提示 |

> 顺序不能随便改：具体游戏名必须在知识白名单之前（"《XX》游戏攻略"含"游戏"也含知识词）。

## 三、类目（学科推荐用）

`classify_category(text)` 返回一个类目，优先级从高到低：

```
游戏/娱乐  >  数学  >  物理  >  学科  >  技术  >  科普  >  技能  >  资讯  >  其他
```

`CAT_PRIORITY`（用于推荐流排序）：
`数学 6, 物理 6, 学科 5, 科普 4, 技术 4, 技能 4, 资讯 2, 其他 0`

首页置顶用的 CSS `order`：
`数学/物理 -4, 学科 -3, 科普/技术/技能 -2, 资讯 -1`

## 四、词表调优的坑

写词表时要注意**泛词误伤**：

| 坑 | 例子 | 处理 |
|---|---|---|
| 品牌/型号含词 | 「方程S」是车模 | 用「解方程」「一次方程」而不是「方程」 |
| 节目名 | 「选择题都选A」是综艺 | 用「单项选择题」「选择题解析」 |
| 金融术语 | 「集合竞价」是股市 | 用「集合运算」而不是「集合」 |
| 学科近义泛词 | 「极限/级数/映射/概率」 | 加限定：「极限思想」「幂级数」「映射关系」「概率论」 |
| 物理近义泛词 | 「碰撞/分解/功」 | 用「动能定理」「动量守恒」「力的分解」「功和能」 |
| 编程撞词 | 「函数」「闭包」 | 技术类优先匹配，或写成「函数图像」 |

改完词表后：

```bash
# 1) 重新分类历史数据
python3 /opt/kbjudge/backfill_cat.py
# 2) 重启（注意：确认进程真的加载了新文件）
systemctl restart mitmfilter kb-judge
# 3) 验证
curl 127.0.0.1:8090/stats
```

## 五、网页名单

- `judge/web_rules.py`：`WEB_ALLOW`（白）/ `WEB_BLOCK`（黑）/ `WEB_EXEMPT`（豁免，仅域名级，不做内容判定）/ `WEB_TITLE_BLOCK`（标题里的娱乐信号）
- 白黑同命中时，**取更长的那条**（更具体优先）
- 运行时追加白名单：`/opt/kbjudge/web_allow.txt` 每行一个域名，**5 秒热加载，不用重启**
  （数据源类域名如 iwencai/sinajs/eastmoney 建议都加进去，否则行情脚本会被门禁误伤）

## 六、LLM 提示词要点

- 视频：`PROMPT` —— 明确"教程/知识讲解/纪录片=知识；实况/娱乐剪辑/混剪=非知识"
- 直播：`LIVE_PROMPT` —— 分区不参与判定（"娱乐"在娱乐词表里会一刀切），只判标题/简介/标签
- 番剧：`PGC_PROMPT` —— 纪录片=知识；动画番剧默认非知识（除非科普教学）；综艺真人秀=非知识
- 输出必须是 `YES` / `NO` 开头的一行，后面跟理由；解析器只认首行

## 七、审计与复核

- 每条裁决落库：`verdicts(bvid, knowledge, reason, source, model, title, ts, aid, cat)`
- 每天 23:50 导出 `audit/audit-YYYY-MM-DD.csv`（`kb-audit.timer`）
- 人工干预：直接改库不推荐，用 `judge` 的 override 接口或清掉对应行让它重判
